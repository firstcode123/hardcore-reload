# 硬汉重回计划 · Hardcore Reload

一套面向久坐办公人群的身体状态回升方案，附带一个零依赖的打卡追踪应用。

> 30 岁不是下坡的起点，是欠账集中到期的节点。
> 这份计划不追求「猛」，只追求「不断」。

## 计划结构

四个阶段，逻辑是「先修复底层，再叠加负荷」：

| 阶段 | 周次 | 目标 |
| --- | --- | --- |
| 地基期 | 第 1–2 周 | 重置作息，只做基础活动，不追强度 |
| 唤醒期 | 第 3–6 周 | 力量每周 3 次 + 心肺基础 |
| 强化期 | 第 7–12 周 | 渐进超负荷，体型与精力变化最明显 |
| 稳固期 | 第 13 周起 | 变成默认值，不再消耗意志力 |

## 打卡与计分

每日 8 项加权合成 0–100「硬汉指数」，75 分为达标线。

| 项目 | 权重 |
| --- | --- |
| 完成训练 | 25 |
| 睡眠达标（23:30 前睡，睡够 7 小时） | 20 |
| 饮食达标 | 12 |
| 步数 8000+ | 10 |
| 睡前 1 小时离屏 | 10 |
| 饮水 2000ml | 8 |
| 久坐打断 4 次 | 8 |
| 颈肩腰放松 5 分钟 | 7 |

数值型项目（睡眠、饮水、步数、久坐）**按达成比例给分**，不是全有全无——睡了 5 小时得 14 分而不是 0 分。

等级：`≥90` 硬汉状态 · `≥75` 状态在线 · `≥60` 及格边缘 · `<60` 今天掉线了

## 数据存储与同步

数据全部保存在浏览器 `localStorage`，**不经过任何服务器**。仓库里只有静态代码，没有个人数据。

由于 `localStorage` 按域名隔离，不同设备默认互不相通，应用提供三种同步方式：

1. **本机保存** — 打开即用，不需要联网
2. **同步码** — 生成一段压缩文本（365 天数据约 8.6KB），跨设备粘贴即可迁移
3. **云同步** — 配置 GitHub Token 后通过私有 Gist 自动双向同步；合并时按天比较时间戳，多端各自打卡不会互相覆盖

## 本地使用

直接用浏览器打开 `index.html` 即可，无需构建、无需依赖。

## 部署

推送到 `main` 分支后，GitHub Actions 自动执行 `.github/workflows/deploy.yml`：
检出 → 筛出静态文件到 `_site/` → 上传 Pages 制品 → 发布。

需要在仓库 `Settings → Pages → Build and deployment → Source` 中选择 **GitHub Actions**。
